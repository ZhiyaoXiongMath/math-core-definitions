# 第二步：根据 Index 筛选并按重要性排名

## 输入与目的

读取当前 INPUT_DIR 的索引清单和全部可用索引文本，必要时分批读取。仅依靠这些 Index 与数学知识筛选、整合和排序；名称模糊时可查看已缓存的对应索引页图像，不转去阅读正文。

用户已经按文件夹分好数学大类。本任务生成该大类内部的概念重要性排名，供后续评价定理涉及的概念使用。概念排名本身不等于定理质量分数，也不评价具体定理的创新性、假设强弱或证明深度。

候选名称必须可追溯到索引条目、子条目或交叉引用。不要凭常识补入未被索引支持的概念。

## 筛选与名称整合

只保留：

- 核心定义：构成该类别主要理论基础，命名中心研究对象、主要数学结构或关键概念。
- 重要定义：理解该类别核心理论、主要定理或关键数学方法所必需的概念。

排除临时记号、局部技术标签、零散辅助词、一般性词语、裸人名、书名及定理名称。作为主要理论工具的概念可以保留，不因其不是最终研究对象而排除。

依据父子条目和 see/see also 恢复完整名称，采用规范英文术语。非英文索引转换为英文名称，不输出双语对照。

仅在当前目录内合并同义和重复项。不要把名称接近、互为特例或关联构造的概念强行合并；对象、条件或范畴不同的概念保留有索引依据的必要限定。不能确认同义时不强合并。

不设置数量配额，不为凑数降低筛选标准。不因书目与目录名称不完全一致而擅自排除已列入的书籍。

## 全局重要性排名：本阶段的主要目标

完成筛选、命名和去重后，先对整个目录中的概念形成一份全局序列，再考虑排版。不要先分主题、先按书排序或先按字母排列，再把结果称为重要性排名。

1. 先确定内部层次：核心定义在前，重要定义在后。层次只用于组织排名，不显示为标签、分数或等级说明。
2. 每个层次内按重要性递减排列，优先比较：
   - 在本类别中心问题、主要理论及主要定理的假设或结论中的结构性地位；
   - 组织和贯穿多个重要结果、联系主要理论部分的能力与适用范围；
   - 对关键方法、重要结构或不变量的必要性与不可替代性。
3. 跨书籍的一致核心地位可辅助判断，但不把出现次数、索引引用页数或书籍数量当作投票权重；同一本书的多个版本不能重复加权。
4. 不把“越基础”“越抽象”“越难”“名称越长”或“越知名”直接等同于越重要。判断其对当前数学大类的实质作用，避免一般性前置术语挤占学科中心概念。
5. 重要性排序高于概念的教学顺序和逻辑依赖顺序。一个概念是另一个概念的前置知识，不自动意味着它必须排得更高。
6. 接近的概念先比较学科中心性和覆盖的重要结果范围；仍无法可靠区分时，用规范英文名称的字母顺序稳定处理近似并列，不编造细粒度的数值差距。
7. 输出前检查相邻概念以及同类、上下位概念是否出现明显倒置；特别复核排名前列是否确实代表本类别中心概念。
8. 可以在工作缓存保留名称、最终名次、内部核心/重要层次及索引来源的简短对应表，便于复核；不将其作为额外交付报告。

最终以 1, 2, 3, ... 的连续编号显示相对排名，1 为最高。编号是顺序，不是重要性分值。不要从清单直接推导某个具体定理的质量得分。

## Section：默认 0 个，上限 3 个

- 默认将整个目录视为一个大类，直接输出一份连续编号的列表，不使用 section。
- 仅当确有少数宽泛分组能改善阅读时，才使用 1–3 个 section；3 是上限，不是目标。
- 先完成全局排名。section 只能把已经排好的序列切成自然、连续的大块，不能为了把同主题条目聚在一起而移动名次。
- 各段合并后的顺序必须仍是同一份全局排名，不能在每节重新从 1 开始，也不能让后节的核心定义落在前节的重要定义之后。
- 如果主题交错，无法在保持排名的同时自然分段，就使用 0 个 section。不要增加细分章节或强行凑成 3 段。

## 输出内容

只允许固定文档标题、可选的宽泛英文 section 标题、排名编号和英文概念名称。

不得输出定义正文、含义解释、重要性理由、核心/重要标签、数值评分、页码、引用、注释、摘要、引言、结论或审查报告，也不将这些内容隐藏在 TeX 注释中。

一个 item 对应一个概念，源码中每项一行，排版允许自然换行。名称所需的标准记号可以保留，例如 $L^2$ cohomology、$\mathrm{Spin}^c$ structure；不写定义公式或性质公式。

## 强制模板格式

读取本技能 assets/core_definitions.tex，复制为 INPUT_DIR/core_definitions.tex 后填写名称。模板中的 Concept name 是示意项，不能保留。

- 导言区、宏包、固定标题、页面设置、author/date、maketitle 和 document 框架保持与模板一致。
- 默认正文仅有一个 enumerate，开头必须为 \begin{enumerate}[series=definitions]。
- 若使用 section：每个 section 紧跟一个 enumerate；第一个列表仍用 [series=definitions]，后续列表必须用 [resume=definitions]，以延续全局编号。
- section 总数最多 3 个，禁止 subsection、嵌套列表、itemize、表格、正文段落或装饰。
- 不混用“无 section 列表”和“有 section 分段”。不写手工编号、不使用 item 的可选标签，也不设置或重置计数器。
- 不添加注释、引用命令、外部输入、自定义宏或额外依赖。

## 检查与交付

先做数学内容检查：索引依据、重要性倒置、核心先于重要、同义合并、类内去重和分段是否改变排名。

再运行 scripts/validate_output.py。它检查固定模板、最多 3 个 section、列表及连续编号语法，不能自动判断重要性排序是否正确。通过后编译检查 core_definitions.tex。

每个目录只交付该 TeX 的文件入口。索引不完整或无法验证编译时，在聊天中简短说明；不凭空补全，不声称通读了正文。
